# 一時ディスクKVキャッシュ追加Fork

Strata v0.2.10（engine 0.1.56）を元にしたソース配布版です。長い会話をBOTが交代で使う際、
以前の会話状態をディスクへ退避し、戻ってきたときの再prefillを減らします。**初期状態はオフ**です。
上流のMITライセンスと著作権表示を維持しています。

## ビルド

このForkの `disk-conversation-cache` ブランチで、[ソースビルド手順](SOURCE_INSTALL.md)に従って
このチェックアウトのエンジンをビルドしてください。上流のリリースバイナリには追加機能はありません。
ビルドコマンド、動作条件、テストの正確なコマンドは[英語の手順](DISK_KV_CACHE_FORK.md)に記載しています。

V100ではCUDA 12.x（検証は12.9）を使用し、CMakeに `-DCMAKE_CUDA_ARCHITECTURES=70 -DSTRATA_EXPERIMENTAL_SM60=ON` を指定します。上流では旧GPU向けのコミュニティビルド扱いです。

対応範囲はLinuxでの逐次処理とlayer splitです。MTPの状態も保存します。`--batch` と `--peer-device` は対象外です。
実機検証したバックエンドはCUDAのみです。この機能を使うためのモデル、APIキー、個人の設定は同梱していません。

## 有効化

既存のモデル設定の `args` に、以下の引数ペアを追加して再起動します。これは設定全体ではありません。
`exe` にはこのForkからビルドしたエンジンを指定してください。

```json
[
  "--conversation-cache-mib", "8192",
  "--conversation-cache-slots", "64",
  "--conversation-cache-min-tokens", "0",
  "--conversation-cache-tier-order", "ram-first",
  "--conversation-cache-dir", "/mnt/fast-cache/strata-kv",
  "--conversation-cache-disk-mib", "12288",
  "--conversation-cache-disk-min-tokens", "60001",
  "--conversation-cache-disk-min-free-mib", "512"
]
```

保存先は例です。選んだストレージがマウントされていることを確認し、サービスユーザー所有の専用ディレクトリに
置き換えてください。他ユーザーが書き込めるディレクトリは使えません。デバイスの自動選択やフォーマットは行いません。
Optaneは必須ではなく、このForkではOptane実機の検証はまだ行っていません。

60,001トークン以上の会話状態を、全GPU分の合計で12 GiBまで保存します。生成済みトークンも状態の長さに含みます。
この例ではRAMに最大8 GiB、最大64会話を保存し、RAMの容量・件数・空きメモリの制約に達すると古い会話をディスクへ移します。
RAMに保存できない大きな会話は直接ディスクへ退避します。短い会話もRAMには保存しますが、ディスクは60,001トークン以上だけです。
RAMの対象も長い会話だけにする場合は `--conversation-cache-min-tokens 60001` にしてください。

`--conversation-cache-tier-order ram-first` が現在の初期値です。RAMが埋まるまではディスクへ会話状態を書きません。
従来のディスク優先動作は `disk-first` で選べます。ディスクが満杯になると、そちらでも最後の利用時刻が古い会話から削除します。
RAMからの退避でもKV全体を複製せず、既にあるRAMデータから分割して書き込みます。全GPU分の保存成功後にディスクへ登録します。

RAMの8 GiBは会話退避用の上限で、モデルや稼働中のチェックポイントを含むプロセス全体の上限ではありません。
既存の空きRAM保護（既定2,560 MiB）は維持します。復元に空きRAMが必要なら古いRAM会話を退避・解放します。
ディスクキャッシュ専用の空き容量保護は既定512 MiBです。通常のセッション保存の空き容量設定とは独立しています。

両GPUのKV、GDNなどの実行状態、最も深い完全な復帰用チェックポイントを一組として扱います。
全ファイルを検証してからGPUへ復元し、大きなKV全体をRAMへ複製せず分割して読み書きします。
RAM保護は維持します。保存・検証失敗は再計算に戻り、GPU転送開始後の復元失敗ではエンジンを終了します。

## 無効化・終了

`--conversation-cache-dir` と保存先を削除するか、`--conversation-cache-disk-mib 0` にして再起動します。
RAMを無効にする場合は `--conversation-cache-mib 0` にします。ディスクのみでも使えます。
RAMを従来の自動設定へ戻す場合は、追加したRAM容量・件数・最小トークン数の引数を削除します。

QUIT/EOFで終了すると一時ファイルを削除します。強制終了・電源断で残ったファイルは、次回起動時に排他ロックを
取得して削除し、再利用しません。強制終了するスーパーバイザーで終了直後に消す場合は、同じ `.lock` を排他的に
取得できることを確認してから `run-*` を削除してください。別の稼働エンジンのファイルは削除しないでください。

## 検証結果

2枚のV100、CUDA 12.9/sm_70、Qwen3.8-Flash-Next IQ3_S、KV k8v4、MTP、262,144コンテキスト、
並列1、layer split 24で検証しました。C++テスト9件、既存APIテスト359件が通過しています。

62,074トークンの合成入力では、初回Prefill約36.2秒に対して、短い会話を挟んだAへの復帰時は約2.5秒、長いBを挟んだ復帰時は
約4.2秒でした。数値は `timings.prompt_ms` の秒換算で、キャッシュ退避・復元を含む入力処理時間です。回答生成（Decode）は含みません。再利用は62,067トークンで、すべて元の実行ファイルと回答が一致しました。第2 GPU用の保存ファイルを
意図的に壊した場合はチェックサム不一致を検出し、再利用0で再計算して同じ回答を返しました。

これは各1回の測定で、OSページキャッシュは消去していません。実機で12 GiBを満杯にする試験は行わず、容量とLRUは
単体テストで検証しています。Optane、他モデル、他バックエンドの性能・動作を保証するものではありません。
詳細な条件と未実施の検証は[英語の検証記録](DISK_KV_CACHE_FORK.md#validation-actually-performed)をご覧ください。

RAM優先の追加検証では、RAMが空いている間にディスクへ書かないこと、古い会話の退避、
全GPU分のKV/MTPを含む保存データの一致、ディスクからRAMへの復帰、保存途中の失敗、明示的な清掃で退避しないことをCPUテストで確認しています。
上記の旧ベンチマークはディスク優先の構成で測定したものです。RAM優先時の性能を表すものではありません。

追加の2 GPU・MTP統合試験は、変更を移植したStrata 0.2.11で実施しました。
RAMの上限件数を試験用に1、ディスク最小トークン数を1にし、2,652トークンのA → 短いS → 短いB → Aで
RAM保存、古いAのディスク退避、2,645トークンの復元と回答一致をログで確認しています。
このKV試験は一時NVMe領域を使用しました。通常設定の60,001トークンしきい値や、8 GiB満杯時の性能測定ではありません。
